Instructions
Plan first, act last. Always double check before executing (measure twice cut once). We are building a live handsfree tracker for Zelda 1 Randomizer. I have the project scoped out into 3 modules. The first module we've been working on already: MODULE 1: ITEM & DUNGEON ITEM TRACKER The data must always be able to be gotten on load, cold, with no observation. Tracker connectivity is guaranteed to drop mid game and if you have to make adjustments it defeats the purpose. When the connectivity drops and then picks up, it should be instantly current, even when things happened in between. INVENTORY: What you currently have, items & triforce pieces DUNGEON ITEMS: Which items are in which dungeon, but only revealed when you have gotten gotten it (location's "taken" bit), as well as when you've gotten its heart container and triforce piece. INFORMATION TO LEARN -Item IDs: there are 8 regular items and 6 special items, as well as 8 triforce pieces. -Item location IDs: rooms in each dungeon where the item is -Taken bits for each item With that you should be able to populate everything in this module. ITEMS Boomerang - 2 variations, regular & magic Bombs Bow, Arrow, Both - depending on what you have it will display as so Candle - 2 variations, blue & red Letter/Potion - 3 variations, Letter/Blue/Red Wand Meat Recorder ITEM LOCATIONS (First Quest) Level 1: 2 items (Second Quest) Level 4: 2 items (Both quests) Level 8: 2 items Level 9: 2 items Every other level has 1 Item. Every level also has a heart and a triforce piece, except level 9. We need the room location of all these items, hearts, and triforces. If we have current inventory, which locations are the main items located, and which items/hearts/triforce have been taken already, we should have everything we need for this module. (TBD) MODULE 2: OVERWORLD CHECK TRACKER MODULE 3: SHAPES DUNGEON MAPPER

Cave Types
There are 20 different cave types in the game, not including levels. The data that defines the cave types is listed below. Some behavior of different cave types may be hard-coded. (The last three appear to be the only cave types that can give out free money.)
 
From	To	Description
045A2		Cave text - Low six bits specify text (values should be multiples of 2), bit 6 specifies whether player can pick up items, and bit 7 is set for shops, potion shops, and pay-to-talk caves.
1860C		Cave Items. 3 Bytes per cave types, format is (high bit first) NMaaaaaa HTbbbbbb PIcccccc. aaaaaa, bbbbbb, and cccccc are value 0-63 that specify item type. Other bits are as follows: N = show prices as negative, M requires player to have enough hearts to get item, H is set for gambling game and secret money, T is set for pay-to-talk caves, P and I specify whether items and prices are visible.
18648		Item prices - 3 bytes per cave
06E6F		Cave dweller - 58 = old man, 59 = old woman, 5A = merchant, 5B = moblin
